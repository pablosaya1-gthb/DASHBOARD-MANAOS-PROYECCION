CÓMO ACTUALIZAR EL TABLERO DE PROYECCIÓN (2025-26)
===================================================

El tablero lee un archivo generado: data/proyeccion.json
NO hay que tocar HTML/CSS/JS: solo regenerar ese JSON con los datos nuevos.

RECETA CORTA (copiar y pegar)
-----------------------------
  pip install polars fastexcel
  python3 scripts/descargar_datos.py
  python3 scripts/procesar_proyeccion.py datos/proyeccion_larga_2025-26.xlsx

Y después subir (commit) el data/proyeccion.json regenerado.


PASO 1 — Conseguir el archivo
-----------------------------
Fuente oficial (Drive, ~158 MB):
  Proyección larga_2025-26.xlsx
  https://docs.google.com/spreadsheets/d/1BxaNGBMDiXbSowF8so1JB1ABMs6ibRra/edit?usp=sharing

  python3 scripts/descargar_datos.py

Lo deja en datos/proyeccion_larga_2025-26.xlsx.
También podés bajarlo a mano desde el navegador y dejarlo en datos/, o pasarle
otro link/id:  python3 scripts/descargar_datos.py OTRO_LINK -o datos/otro.xlsx

Requisito: el archivo tiene que estar compartido como "cualquiera con el enlace".


PASO 2 — Regenerar el JSON
--------------------------
  pip install polars fastexcel        (solo la primera vez)
  python3 scripts/procesar_proyeccion.py datos/proyeccion_larga_2025-26.xlsx

Acepta .xlsx, .xlsm, .csv (separador ; ) y .zip con cualquiera de los dos adentro.
Si no le pasás ruta, busca solo en datos/ y en la raíz.

Opciones:
  --hoja NOMBRE   elegir la hoja del Excel (por defecto, la primera)
  --via-csv       convierte el Excel a CSV en streaming antes de procesar.
                  Usa MUCHA menos memoria (necesita: pip install openpyxl).
                  Recomendado si la PC tiene menos de 8 GB de RAM.
  --salida RUTA   escribir el JSON en otro lado (para comparar antes de pisar
                  el actual: --salida /tmp/nuevo.json)

El script imprime al final la validación (bruto/neto totales, ajustes excluidos,
meses detectados y cuáles quedaron parciales). Si los totales no cuadran con el
ERP, revisá antes de publicar.


PASO 3 — Publicar
-----------------
Subir (commit) el data/proyeccion.json regenerado a la rama y recargar el tablero.
Si usan GitHub Pages sobre esta rama, se actualiza solo.


QUÉ SE ACTUALIZA SOLO (ya no hay que tocar el código)
-----------------------------------------------------
- CANTIDAD DE MESES: si la próxima carga trae 21, 24 o los que sean, el ETL arma
  las etiquetas desde la primera fecha y el tablero se adapta solo (antes estaba
  clavado en 20 meses tanto en el script como en app.js).
- MES PARCIAL: el ETL detecta solo si el último mes viene incompleto (por ejemplo
  "solo desde el 20/07/2026") y el tablero lo marca en el header, en el filtro de
  período (⚠) y con barra naranja en la serie mensual.
- COLUMNA MES: si no viene o viene vacía, se reconstruye desde la Fecha.
- NOMBRES DE COLUMNAS: tolera acentos/mayúsculas/espacios distintos ("Línea",
  "LINEA ", "Linea").
- AJUSTES CONTABLES ("DIFERENCIAS/AJUSTES") se excluyen solos del cube comercial.
